# F4 — Animation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Play glTF animations deterministically at an explicit time:
- translation / rotation / scale / weights with LINEAR, STEP and CUBICSPLINE;
- KHR_animation_pointer for node, mesh, material, light and camera properties;
- GPU skinning (up to 8 influences, several skins) and morph targets (POSITION / NORMAL / TANGENT / TEXCOORD_0..1 / COLOR_0) per frame on T1/T2, with the documented T0 fallbacks.

Animated Sample-Assets must match Sample-Viewer references taken at the same timestamps, on Vulkan and D3D11 and on a D3D11 FL10_0 (T0) leg.

**Architecture:**
- `engine/scene/Animation.{h,cpp}` is the sampler and pose evaluator. It is extracted from the t = 0 code that F3 already has in `engine/scene/Scene.cpp` (`interpolate`, `animate`), so there is one sampler, not two.
- `scene::updatePose` recomputes, per frame:
  - world matrices, joint matrices and morph weights;
  - lights, cameras and material overrides;
  - animated bounds.
- The renderer writes the per-frame data into **dynamic buffers**. This is a new RHI feature: `BufferDesc::dynamic` + `IDevice::updateBuffer`, one copy per frame in flight. Static scenes write nothing per frame, so the F2/F3 images stay byte-identical.
- At T0, a primitive the shader paths cannot draw exactly goes through a CPU deformer: morph first, then skin, as the shader does.
- The fit camera stays on the rest pose, as Sample-Viewer's does.
- The §6 resolver is F5. F4 reports only a minimal ON / FALLBACK / OFF(reason) per feature in `SceneInfo::features`, and F5 absorbs it.

**Tech Stack:** C++20/23 as F3 (`engine`, `std::expected`), the F2 RHI (Vulkan, D3D11), the F1 `shaderc`, fastgltf v1.0.1 (pinned) plus a raw-JSON pass for animation channel targets, Dear ImGui (viewer), Python 3 stdlib (scripts), and `tools/refgen` (Firefox + Puppeteer, `@khronosgroup/gltf-viewer` 1.1.0).

**Spec:** `docs/superpowers/specs/2026-11-27-cross-platform-gltf-renderer-design.md`:
- §7.1 (skin, morph "+ ek attribute'lar", animation, perspective + orthographic camera), §7.2 (`KHR_animation_pointer`), §7.3;
- §6.1 / §6.2 (Skinning and Morph rows), §8, §10, §11 F4, §12;
- §14 K-A, K-B, K-C, K-D, K-E.

Also read the F3 plan (`docs/superpowers/plans/2026-11-28-f03-gltf-loader-core-pbr.md`), `tools/refgen/README.md` and `tests/golden/ref/sample-viewer/settings.json`.

  - no process kills;
  - reviewers clone from origin at a short path (CLAUDE.md);
  - CI and Metal are PENDING-CI;
  - no browser download, and refgen uses Firefox only;
  - reference mode reproduces `settings.json` by value;
  - unbounded inputs are capped by cvars with a warning, never a crash;
  - commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Animation semantics follow Sample-Renderer 1.1.0 by value.** The source is `tools/refgen/node_modules/@khronosgroup/gltf-viewer/dist/gltf-viewer.js`, classes `gltfInterpolator` and `gltfAnimation`. Cite the class in a comment where each rule is ported:
  - `maxTime` = the largest last input key over the animation's channels;
  - `t = t % maxTime` (JS remainder: keeps the sign; `t == maxTime` wraps to 0), then clamped to the channel's `[input[0], input[last]]`;
  - next key = the first `i` with `t <= input[i]`, clamped to `[1, n-1]`; previous key = next key - 1; `tn = (t - in[prev]) / (in[next] - in[prev])`. So STEP at an exact key time returns the *previous* key;
  - a sampler whose output has exactly `stride` elements returns them, with no interpolation;
  - rotation:
    - LINEAR: normalize both keys, glMatrix `slerp` (shortest path), then normalize;
    - CUBICSPLINE: the component-wise spline, then normalize;
    - STEP: the previous key;
  - CUBICSPLINE tangents are multiplied by `keyDelta`; the element layout is in-tangent, value, out-tangent;
  - a `weights` channel animates `node.weights` when the node has them, else `mesh.weights` (shared by every node of that mesh, as Sample-Renderer does);
  - time arithmetic is in `double`, outputs are `float`.
- **Played set:** by default every animation that does not overlap an earlier one, in index order (gltf.js `nonDisjointAnimations`, as refgen). Headless renders at `--time` (default 0). With time 0 and the default set, every F2/F3 golden image is byte-identical to F3.
- **T0 limits (K-E)**, as cvars:
  - `r.Skin.T0MaxJoints` (default 64, max 64 = `T0_MAX_JOINTS`);
  - `r.Morph.T0MaxTargets` (default 8, max 8 = `T0_MAX_MORPH_TARGETS`).

  T0 skinning and morphing are always FALLBACK, never OFF (K-C, §6.2).
- **Caps** (LoadOptions + cvars; exceeding one gives a warning, never a crash):
  - `r.Asset.MaxAnimationKeys` (default 1,048,576 per sampler): the channel is dropped;
  - `r.Asset.MaxJoints` (default 4096 per skin): the skin is ignored and the node draws unskinned;
  - `r.Asset.MaxMorphTargets` (default 256 per primitive): the first N targets are used.
- **Permutations:** no new axis. The matrix stays TIER × FG_SKIN × FG_MORPH × FG_UNLIT (K-A ≤ 64 per backend); `compile_shaders` counts stay as F3: pbr 128 total / 112 ok / 0 failed / 16 msl PENDING-CI; the whole library (`--library shaders/library.json`) 252 / 228 / 0 / 24.
- **Golden thresholds (K-C):**
  - T1/T2 vs Sample-Viewer: default mean FLIP 0.05;
  - T0 vs Sample-Viewer: ≤ 0.10 with a reason (sanity), plus a compare case T0 vs the same backend at FL11 ≤ 0.01 (regression);
  - every non-default threshold has a `thresholdReason`;
  - `expectedFail` is at most 10% of its case set, and never covers a crash or a non-zero headless exit (Task 1).
- **Facade:** every change is logged in `docs/facade-changelog.md` under "F4". The facade freezes in F7.
- **Bench (K-E):** compare with interleaved medians (5 × 300 frames, Release, 2560×1440) against the F3 gate binary. More than 10% regression on any F3 bench scene = gate FAIL.

## Review Focus

1. **Hostile animation / skin data.** These must give exit 2 with a message, or a warning when a cap applies, and never a crash, NaN, hang or GPU out-of-bounds read:
   - input/output count mismatch (also for CUBICSPLINE ×3 and weights × target count);
   - non-increasing or negative key times;
   - NaN/Inf keys or values;
   - a rotation output that is not VEC4;
   - `2^31` accessor counts;
   - counts above the caps;
   - a JOINTS index ≥ the skin's joint count (this must never reach the GPU);
   - a skin without `inverseBindMatrices` (identity, renders).

   Task 2 owns these, with fixtures under `tests/assets/f04/bad/` run under ASan.
2. **Extreme times.**
   - `--time` NaN / Inf gives a usage error (exit 2).
   - A negative or a huge time (1e30) renders the clamped first key or the wrapped value as Sample-Viewer does.
   - `t == duration` wraps to 0.
   - A single-key animation and `maxTime == 0` give the constant value.

   Task 2 unit tests, Task 3 headless test.
3. **Degenerate animated poses.**
   - An animated scale of 0 (singular world matrix) skips that draw and sends no NaN to the GPU.
   - A scale whose sign flips over time switches the triangle winding on that frame.

   Task 3 test, fixture `tests/assets/f04/scale_flip.gltf`.
4. **Shared and recursive skeletons.**
   - One mesh used by two nodes with two different skins.
   - Two skins sharing joints.
   - A joint that is an ancestor of the skinned mesh node (RecursiveSkeletons).
   - The skinned mesh node's own transform must not apply twice (`inverse(world(meshNode))`, F3 Scene.h).

   Task 4 tests.
5. **Resource churn while animating.** These must give validation 0, no stale dynamic buffer, and no use-after-free:
   - changing the active animation set;
   - `destroyScene` / `releaseAsset` of an animated scene;
   - a viewer drag-and-drop of an animated asset over another;
   - toggling `r.Animation.Loop` mid-run.

   Task 3 facade test, Task 7 viewer test.
